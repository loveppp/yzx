# 项目快速入门

> 面向第一次接触本仓库的同事：用最少时间搞清 **这是什么、怎么跑、改内容改哪、上线怎么走**。  
> 日常维护细节见 [项目说明与使用指南](./项目说明与使用指南.md)，部署见 [DEPLOYMENT.md](./DEPLOYMENT.md)。

---

## 1. 项目是什么

| 项 | 说明 |
|----|------|
| 业务 | 深圳市源智信（YZX Precision）**模具配件 B2B 外贸独立站** |
| 目标 | 展示产品系列、工厂与定制能力，引导 **询价 / WhatsApp**，不是在线商城 |
| 技术 | **Astro 5** 静态站点 + Tailwind + 少量 **React**（询价表单） |
| 语言 | 英语 `en`、简体中文 `zh`、越南语 `vi`（URL 带语言前缀） |
| 规模 | 以 `src/data/catalog.json` 为准（当前约 **6 个大类、27 个产品系列**） |

**维护原则**：产品信息以 `src/data/catalog*.json` 为唯一真相来源；页面从数据自动生成，没有 WordPress 式后台。

## 2. 两种「运行方式」（必分清）

### 2.1 开发机：有 Node 进程

你在本机执行 `npm run dev` 时，**Astro 开发服务器**在内存里读 `src/` + `public/`，实时拼 HTML。

```
npm run dev
  → scripts/dev.sh
  → scripts/use-node20.sh（尽量用 Node 20）
  → astro dev --host
  → 浏览器 http://localhost:4321
```

根路径 `/` 会 **302 到** `/en/`（见 `src/pages/index.astro`）。

### 2.2 线上（腾讯云 IP）：没有 Node，只有静态文件

线上 **不跑** `npm run dev`。流程是：

```
本机 npm run build  →  生成 dist/
  →  rsync/scp 上传到服务器 /var/www/yzx/
  →  Nginx 直接返回 HTML / 图片 / CSS / JS
```

访客例如：`http://159.75.252.43/zh/` 读到的是 **已经生成好的** `dist/zh/index.html`。

### 2.3 询价 API（第三条线，可选）

表单组件 `QuoteForm.tsx` 会向 **`POST /api/quote`** 发请求。

| 部署方式 | 表单能否提交 |
|----------|----------------|
| 腾讯云 Nginx **只托管 dist** | **不能**（无后端处理 POST） |
| **Cloudflare Pages** | **能**，使用 `functions/api/quote.ts` + Resend 发邮件 |

详见 [DEPLOYMENT.md](./DEPLOYMENT.md)。

## 3. 命令入口（package.json）

| 命令 | 作用 |
|------|------|
| `npm install` | 首次安装依赖（`node_modules/`） |
| `npm run dev` | 本地开发，默认 http://localhost:4321 |
| `npm run build` | 准备 redirects → 校验 catalog → 类型检查 → 生成 **dist/** |
| `npm run preview` | 本地预览 **dist/**（模拟上线效果） |
| `npm run catalog:check` | 只校验产品与图片，不构建 |

**Node 版本**：>= 18.20.8，推荐 20。Mac 上脚本会优先用 `~/.local/node-v20.18.3-darwin-x64/bin`。

### build 内部顺序

```
npm run build
  1. node scripts/prepare-catalog.mjs   → 写 public/_redirects（旧 URL 301）
  2. node scripts/check-catalog.mjs     → catalog 与图片一致性
  3. astro check                        → TS/模板检查
  4. astro build                        → 输出 dist/ + sitemap 等
```

构建产物 **`dist/`** 不要手改；改 `src/` 或 `public/` 后重新 build。

## 4. 请求是怎么变成页面的（运行链路）

以访问 **`/zh/products/punch-components/carbide-punches/`** 为例：

```
浏览器请求 URL
    ↓
Nginx（线上）或 astro dev（本地）找到对应静态文件 / 或现算 HTML
    ↓
页面文件：src/pages/[locale]/products/[category]/[slug].astro
    ↓
读取数据：
    - src/data/catalog.json          （系列名称、摘要、主图…）
    - src/data/catalog-details.json  （各配置 variant）
    - src/data/catalog-detail-media.json （配置细节图）
    - src/data/catalog-family-extras.json （长文、FAQ、应用场景）
    - src/data/catalog-family-figures.json （长文配图路径）
    - src/data/catalog-ui.ts         （产品页通用按钮、流程、FAQ 模板文案）
    ↓
组件拼装：CatalogFamilyDetails、ProductMedia、QuoteSection…
    ↓
外层：src/layouts/Layout.astro（导航、页脚、SeoHead）
    ↓
返回 HTML
```

**React 仅用于询价表单** `src/components/QuoteForm.tsx`，其余多为 Astro 输出的静态 HTML。

## 5. 目录地图：先看什么、后看什么

### 5.1 根目录

| 路径 | 是否优先看 | 说明 |
|------|------------|------|
| **src/** | ★★★ | 页面、数据、文案、组件 |
| **public/** | ★★★ | 图片、robots.txt、favicon；路径与 JSON 中 `image` 字段对应 |
| **docs/** | ★★ | 文档（本文件、部署、目录维护） |
| **package.json** | ★★ | 脚本入口 |
| **astro.config.mjs** | ★ | 站点 URL、多语言、sitemap |
| **scripts/** | ★ | 构建、检查、出图 CLI；改内容阶段少碰 |
| **functions/** | 可选 | Cloudflare 询价 API |
| **data/catalog/** | 可选 | 图片策划 brief（出图用） |
| **output/** | 忽略 | 本地候选图，不提交 Git |
| **dist/** | 忽略 | build 生成 |
| **node_modules/** | 忽略 | 依赖 |

### 5.2 `src/` 内部

```
src/
├── pages/                 # URL 入口（文件路由）
│   ├── index.astro        # / → 跳转 /en/
│   └── [locale]/          # /en/ /zh/ /vi/ 下所有页面
├── layouts/Layout.astro   # 全站壳：Nav、Footer、SEO
├── components/            # 页面区块（改样式/结构才深入）
├── data/                  # ★ 产品核心 JSON + 少量 .ts
├── i18n/messages/         # ★ 全站 UI 文案（首页、工厂、联系…）
├── content/blog/          # ★ 博客 Markdown
└── styles/global.css
```

### 5.3 推荐阅读顺序（30～60 分钟）

1. 本文 **第 2、3、4 节**（怎么跑、怎么 build）
2. [项目说明与使用指南](./项目说明与使用指南.md) 的「网站信息架构」「改内容改哪里」
3. `src/data/catalog.json` — 打开一个系列对照网页
4. `src/i18n/messages/zh.json` — 首页、导航、联系
5. `npm run dev` + 浏览器对照 `/zh/` 与一个产品页
6. 需要写 SEO 长文时再看 `catalog-family-extras.json`
7. 写博客：`src/content/blog/` 任一篇 + `content/config.ts` 字段说明

## 6. URL 与页面对照表

| 页面 | URL 示例 | 源文件 |
|------|----------|--------|
| 根 | `/` | `src/pages/index.astro` → 重定向 |
| 首页 | `/zh/` | `src/pages/[locale]/index.astro` |
| 产品总览 | `/zh/products/` | `src/pages/[locale]/products/index.astro` |
| 产品大类 | `/zh/products/punch-components/` | `src/pages/[locale]/products/[category]/index.astro` |
| **产品系列** | `/zh/products/punch-components/carbide-punches/` | `src/pages/[locale]/products/[category]/[slug].astro` |
| 定制 OEM | `/zh/custom-oem/` | `src/pages/[locale]/custom-oem/index.astro` |
| 工厂 | `/zh/factory/` | `src/pages/[locale]/factory/index.astro` |
| 博客列表 | `/zh/blog/` | `src/pages/[locale]/blog/index.astro` |
| 博客文章 | `/zh/blog/ejector-pin-material-guide/` | `src/pages/[locale]/blog/[slug].astro` + `src/content/blog/*.md` |
| 联系 | `/zh/contact/` | `src/pages/[locale]/contact/index.astro` |

- `[locale]`：`en` | `zh` | `vi`
- `[category]`：`catalog.json` → `groups[].id`
- `[slug]`：`catalog.json` → `products[].id`

导航里的产品下拉 **直接来自 catalog**，不是 `messages` 里旧的 productMega 链接表。

## 7. 改内容改哪里（速查）

| 想改什么 | 文件 |
|----------|------|
| 系列名称、摘要、材质、主图路径 | `src/data/catalog.json` |
| 某系列下各配置（Type A…）说明与参数 | `src/data/catalog-details.json` |
| 配置对应的细节图 | `src/data/catalog-detail-media.json` + `public/images/products/details/` |
| 系列长文（应用、优势、额外 FAQ） | `src/data/catalog-family-extras.json` |
| 长文区块配图路径 | `src/data/catalog-family-figures.json` + `public/images/products/family-sections/` |
| 首页 slogan、导航、联系、工厂文案 | `src/i18n/messages/en.json` / `zh.json` / `vi.json` |
| 产品列表/详情页通用话术（询价、流程 FAQ） | `src/data/catalog-ui.ts` |
| 博客 | 新建 `src/content/blog/xxx.md`（英中字段见现有文章） |
| 旧站 URL 跳转 | `src/data/catalog-legacy.json`（build 写入 `public/_redirects`） |
| SEO 标题/描述（全站 head） | `src/components/SeoHead.astro` + 各页 `Layout title/description` |
| 站点域名（canonical/sitemap） | `astro.config.mjs` 的 `site` |

改完产品相关 JSON 后建议执行：`npm run catalog:check`。

## 8. 产品数据五件套（系列页）

对一个系列（如 `carbide-punches`），内容分布在：

```
catalog.json              → 名片：name, summary, materials, image
catalog-details.json      → 配置列表 variants[]
catalog-detail-media.json → 每个 variant 的图
catalog-family-extras.json→ SEO 长文、FAQ、开关（是否隐藏配置区等）
catalog-family-figures.json→ 长文配图
```

页面模板 **`[slug].astro`** 负责排版，**日常改字优先改 JSON**。

## 9. 图片放在哪

| 用途 | 目录 |
|------|------|
| 系列主图 | `public/images/products/catalog/` |
| 配置细节图 | `public/images/products/details/` |
| 长文配图 | `public/images/products/family-sections/` |
| 无实拍时的 SVG | `public/images/catalog/*.svg` |
| 品牌 / 工厂 | `public/images/brand/`、`public/images/factory/` |

JSON 里的路径以 **`/images/...`** 开头，对应 `public/images/...` 文件。

## 10. 部署速览

| 环境 | 做法 |
|------|------|
| 本地 | `npm run dev` |
| 腾讯云 CVM | `npm run build` → 上传整个 **dist/** 到 `/var/www/yzx` → Nginx 静态托管 |
| Cloudflare Pages | Build: `npm run build`，Output: `dist`；配置 Resend 环境变量 |

当前文档记录的测试访问：`http://159.75.252.43/zh/`。正式 SEO 建议使用 **域名 + HTTPS**（与 `astro.config.mjs` 中 `https://yzxprecision.com` 一致）。

上传命令示例见 [DEPLOYMENT.md](./DEPLOYMENT.md)。

## 14. 一句话总结

**开发时**：`npm run dev`，改 `src/data` 和 `src/i18n` 和 `content/blog`，Astro 在 4321 端口拼页面。  
**上线时**：`npm run build` 得到 `dist/`，服务器只发静态文件；询价要 Cloudflare 或自建 API。  
**改产品**：从 `catalog.json` 开始，系列页再加 `catalog-details` 与 `catalog-family-extras`。
